# Learn to DataNetworking 2.6

Learn to DataNetworking 是一款面向 eNSP、EVE-NG 和 PNETLab 网络模拟环境的管理工具，通过网页和 MCP 接口提供设备连接、命令执行、拓扑分析、流量监控及 AI 辅助操作。

当前版本 **2.6**。应用目录保留原路径，以兼容已有启动配置。版本变更见 [更新记录](../CHANGELOG.md)。

## 功能概览

### Web 界面

| 模块 | 功能 |
|------|------|
| 端口扫描 | 扫描指定 IP 的端口范围，发现 eNSP 设备（默认起始端口 2000） |
| 设备连接 | 通过 Telnet 连接设备，每个设备拥有独立的终端标签页 |
| 命令执行 | 向已连接设备发送命令（如 `display version`）并实时查看返回结果 |
| 拓扑分析 | 上传 eNSP `.topo` 或 EVE-NG / PNETLab `.unl` 文件，生成拓扑图和互联信息 |
| 流量和报文 | 在拓扑图上查看估算流量、数据包分析和慢放溯源 |
| AI 对话 | 使用自然语言调用 MCP，辅助查询和操作设备 |
| 界面设置 | 调整 AI 对话栏宽度，切换深色或浅色主题 |

### MCP 工具

| 工具名 | 功能 |
|--------|------|
| `scan_ports` | 扫描目标 IP 的端口范围 |
| `connect_device` | Telnet 连接设备 |
| `send_command` | 向设备发送命令 |
| `disconnect_device` | 断开设备连接 |
| `list_sessions` | 列出当前所有活跃会话 |
| `get_device_info` | 获取设备基本信息 |
| `get_topo_report` | 获取已上传拓扑的分析报告 |
| `detect_topology_devices` | 检测拓扑设备的本机或远程控制台端口和会话 |
| `get_topology_links` | 读取当前拓扑的互联设备、接口来源与会话，支持按设备名筛选和分页 |

## 快速开始

### 1. 安装依赖

```powershell
python -m pip install -r requirements.txt
```

在本目录执行命令。使用设备功能前，请先启动 eNSP 中的目标设备；流量监控还需要 Wireshark（包含 `tshark`）、Npcap 和可访问的 VirtualBox Host-Only 网卡。

### 2. 启动服务

```bash
python app.py
```

启动后同时运行两个服务：

```
============================================================
  Learn to DataNetworking
  Web 界面: http://0.0.0.0:5000
  MCP SSE:  http://0.0.0.0:5001/sse
============================================================
```

浏览器打开 `http://localhost:5000` 即可使用 Web 界面。

## 使用流程

### 设备终端命令补全

连接设备后，在终端输入框中输入命令即可显示本地候选，例如 `dis ip int b` 可补全为 `display ip interface brief`。按 **Tab** 填入当前候选，**↑/↓** 选择候选，**Esc** 关闭列表，也可鼠标点击候选。候选打开时回车填入所选内容，填入后再次回车发送；已完整输入的词库命令可直接回车发送。Shift+Tab 保留浏览器的焦点切换。

补全按拓扑型号提供华为 VRP、Cisco、Linux 或 VPCS 的常用命令，并从当前互联信息补充该设备的接口名，支持 eNSP 和 EVE/PNET 的远程会话。未知型号提供通用建议并提示核对厂商。建议来自本地词库、当前拓扑及会话历史，不查询设备实时命令树，也不判断当前配置视图或实际支持情况；接口记录仍需按其来源核对。

候选关闭时，↑/↓ 可翻查本次终端会话的命令历史，并在返回最新位置时恢复尚未发送的草稿。历史最多 100 条，仅保存在当前页面内存，刷新或断开会话后清空；密码、community 等凭据相关命令不加入补全历史。补全本身只修改输入框，不发送设备命令。

### AI 对话与 MCP

AI 对话支持兼容 OpenAI Chat Completions 且支持工具调用的模型。可以在网页右侧「AI 设置」中填写 API 基础地址、模型名称和密钥。点击「保存对话」可将对话和显示的 MCP 输出保存到当前浏览器，刷新后可使用「恢复对话」；「删除保存」会清除该浏览器中的保存记录。「导出对话」可将当前页面显示的对话和 MCP 输出下载为文本文件。保存或导出的内容可能包含设备信息和命令输出，请勿保存敏感信息。设备连接、AI 设置中的密钥和待确认操作不会随对话恢复。

使用 DeepSeek 时，在「模型模板」选择「DeepSeek Flash」或「DeepSeek V4 Pro」，页面会填入官方地址 `https://api.deepseek.com` 和对应的 `deepseek-flash` 或 `deepseek-v4-pro` 模型名。填写 DeepSeek API 密钥并保存后即可对话；从其他服务切换时需填写新密钥或清除旧密钥。为兼容网页保存的对话历史和 MCP 工具调用，DeepSeek 请求使用非思考模式。也可以选择「自定义」并手动修改地址和模型。已保存的旧模型名不会自动更改，请手动选择新模板。

AI 设置中的「网络连接」默认使用系统代理；如果代理导致连接中断，可手动选择「直连（不使用代理）」并保存。这只影响 AI 服务请求。

保存设置后可点击「测试已保存设置」检查 AI 服务认证和回复；该测试会向模型发送一条简短请求，可能产生少量 API 费用，不会调用设备或 MCP 工具。DeepSeek 返回 HTTP 401 表示密钥认证失败；HTTP 402 表示账户余额不足。

网页设置只保存在当前 Web 服务进程的内存中，重启后恢复为环境变量的值；密钥不会在页面中回显。地址与模型为必填，密钥留空保留当前值，也可勾选清除；更改设置会取消待确认的工具调用。远程服务必须使用 HTTPS，本机服务可使用 HTTP。

也可以在启动服务前，通过 PowerShell 设置环境变量：

```powershell
$env:ENSP_AI_BASE_URL = 'https://你的服务地址/v1'
$env:ENSP_AI_MODEL = '你的模型名称'
$env:ENSP_AI_API_KEY = '你的密钥'
python app.py
```

密钥可按服务商方式安全设置为环境变量，不要写入仓库；无需密钥的本地服务可省略。地址应是 API 的基础路径，程序会追加 `/chat/completions`。打开「AI 对话」后输入需求，模型通过本机 MCP SSE 工具查询或操作设备，并可根据已上传拓扑的端口自动检测设备。**「自动执行」默认开启**：操作类工具（包括设备配置命令）会直接运行；取消勾选后须逐次确认，取消或 5 分钟未确认即失效。未手动保存的对话在刷新后清空。

对话内容、已调用的工具结果和设备命令输出会发送给所配置的 AI 服务。AI 对话接口仅允许本机访问，Web 与 MCP SSE 服务都须正常运行。不同服务商对工具调用的兼容程度可能不同。

### 扫描与连接设备

1. 在左侧"端口扫描"面板输入目标 IP 和端口范围
2. 点击"开始扫描"发现开放的设备端口
3. 在"设备列表"中点击"连接"建立 Telnet 会话
4. 在底部终端输入命令（如 `display version`），按回车发送
5. 每个已连接设备有独立标签页，可随时切换

### 拓扑分析

支持上传 EVE-NG / PNETLab `.unl` 拓扑，按节点、接口和网络关系绘图；文件中的接口名称标记为「拓扑文件声明，未经验证」。隐藏的双端桥接网络显示为直连链路，共享网络和外部网络显示为网络节点。`.unl` 文件不会提供运行时控制台地址，需要按下述步骤接入服务器。

#### EVE-NG / PNETLab 接入

1. 上传 `.unl` 文件，在「拓扑分析 → EVE-NG / PNETLab 服务器」填写服务器根地址，例如 `http://192.168.52.128`。也可直接填写 `/legacy/topology` 页面地址，程序会转换为根地址。
2. EVE-NG：选择 EVE-NG，填写实验路径（如 `/实验/SNMP.unl`）、用户名和密码。PNETLab：先在原网站登录并打开相同实验，从浏览器开发者工具的网络请求复制 Cookie，在本机网页的密码框中填写；支持原网站要求验证码的登录流程。
3. 点击「接入服务器」，再到「设备列表」点击「一键连接拓扑设备」。程序核对节点 ID、名称、型号和节点集合，读取 API 返回的 Telnet URL；不会按节点编号猜测端口。服务器返回回环控制台地址时，使用服务器主机地址连接。
4. 设备列表和终端标签显示「设备名（端口号）」，会话按主机和端口匹配。设备列表可切换到端口扫描结果。VNC、未返回 Telnet URL 或地址不可用的控制台会显示不可用。
5. 华为 VRP 模板支持现有的改名、全局 LLDP 检查/启用和双向邻居验证流程；其他厂商可使用终端或 AI 发送对应命令，不自动套用华为配置。共享网段不会被误报为双设备直连验证成功；平行直连链路仅在文件声明接口与双向 LLDP 均匹配时分别确认。

互联信息手动填写、导入、导出和浏览器保存同样适用于 `.unl`。AI 的 `detect_topology_devices` 和 `get_topology_links` 使用远程控制台 IP/端口及接口来源，辅助配置链路地址。服务器认证、Cookie 和 SSH 凭据仅保存在当前服务内存，不导出到互联信息或发送到 AI；重启服务后重新接入。服务器 API 使用直连和标准 TLS 证书校验。

#### EVE-NG / PNETLab 流量监控

在服务器设置内展开「远程流量抓包（SSH）」，填写 SSH 主机、用户名、密码或使用本机 SSH 密钥。主机需已存在于 `~/.ssh/known_hosts`，也可填写经服务器核对的 SHA256 指纹；不会自动信任未知主机。服务器须安装 `iproute2` 和 `tcpdump`，SSH 用户须有直接抓包权限（不自动提权）。

连接 SSH 后，在拓扑图的「远程抓包链路映射」为需监控的连线选择真实 TAP 网卡，再点击「开始监控」。可同时选择最多 32 条链路；每条选一端，禁止同一网卡重复映射。程序读取真实服务器网卡，不推算 EVE 的 pod/TAP 编号。共享网桥上的抓包包含整个网段，请根据实际服务器连接选择网卡。

监控显示映射链路的包速率、比特速率及最近 200 个以太网报文，沿用 IPv4、IPv6、ARP、ICMP、TCP、UDP 和 OSPF 分析。映射由用户指定，并非 LLDP 验证；原始以太网抓包不能确认拓扑发送端，因此远程报文不播放带方向的慢放动画。停止或更换拓扑时关闭远程抓包会话；未映射链路显示「未覆盖」。

1. 在 eNSP 中导出拓扑文件（`.topo` / `.txt`）
2. 在左侧"拓扑分析"面板点击"上传拓扑文件"
3. 在拓扑图查看设备、连线和互联信息；可验证接口或导入、导出接口记录
4. MCP 工具 `get_topo_report` 可读取拓扑分析结果；重启 Web 服务后需重新上传拓扑

拓扑图支持滚轮或加减按钮缩放、拖动画布平移，并可通过「适应画布」恢复初始视图。路由器与交换机使用不同图标；图旁的「互联信息」按物理连线列出两端设备，未确认的接口显示「待验证」，验证后显示接口名称。

报告中的接口名称和网络层级包含推断结果，执行设备配置前应以设备实际信息为准。可使用「删除」清除当前拓扑及报告。

上传拓扑后，在设备列表点击「一键连接拓扑设备」，根据拓扑的本机端口复用或建立会话；程序跳过 PC、AP 和 Server，连接操作不修改设备配置。然后在拓扑分析点击「验证链路接口」，通过 MCP 先尝试将其余设备名设为拓扑名称。改名阶段结束后，对改名成功的设备检查并启用全局 LLDP，查询 `display lldp neighbor brief`，通过两端设备的邻居表相互核对设备名和接口名。程序不查询接口清单，也不修改接口级 LLDP；接口级 LLDP 关闭时该链路可能无法发现。操作修改运行配置，不自动保存。被跳过设备的连线、未连接、配置失败、邻居未发现、查询不完整、名称重复或存在并行连线时，继续显示「待验证」。一次最多处理 32 台设备。

验证期间发现可确认的链路时页面自动刷新互联信息；没有足够证据的连线显示「待验证」。未读取到身份的设备仍可能与已读取设备重名，链路匹配依赖当前可见的设备名称和双向 LLDP 信息。设备连接日志和验证日志可点击标题展开或折叠；验证日志默认折叠，进度和结果摘要保持可见。

互联信息中可为每条连线手动填写一端或两端接口名，结果标记为「手动填写，未经验证」，也可清除手动内容恢复自动结果。手动内容仅在当前服务运行期间保留，重新上传或删除拓扑时清空。

拓扑分析中的「导出互联信息」可将手动接口和已验证接口保存为 JSON 文件。下次上传相同拓扑后，点击「导入互联信息」恢复；文件通过设备 ID、名称、型号和链路端点匹配拓扑，拓扑不一致时会拒绝导入。历史验证结果标记为「当前未重新验证」，不会声称设备当前状态未变；手动内容仍标记为未经验证。导入会替换当前手动和历史记录，不会修改设备配置或覆盖本次 LLDP 验证结果。

也可以点击「保存链路信息」保存到当前浏览器，下次上传相同拓扑后点击「恢复已保存链路」。保存包括已验证和手动填写的接口，不包含设备配置；恢复时会替换当前手动和历史记录。本地记录只在当前浏览器中可用，清除浏览器数据后会丢失，需要跨浏览器使用时可导出 JSON。

AI 可通过只读 MCP 工具 `get_topology_links` 查询当前互联信息，用于理解链路和辅助配置接口 IP。返回内容包含手动或 LLDP 接口的来源、两者是否冲突，以及设备会话；手动接口仍须结合设备实际配置核对。数据来自当前服务内存，重新上传、删除拓扑或重启服务后不会保留。对话中可直接要求「查看 AR1 的互联接口」或「根据 AR1 与 AR2 的互联信息规划 IP」。

所有设备的改名尝试结束后，程序统一等待 5 秒，再处理改名成功设备的 LLDP 配置。

改名前先在用户视图发送 `screen-length 0 temporary`，等待 0.5 秒后继续，不检查设备回显；该设置不保存为设备配置，是否成功取决于设备支持情况。

### 拓扑流量监控

安装 Wireshark 和 Npcap，启动 eNSP 设备并上传拓扑，打开「拓扑图」，选择 eNSP 使用的 VirtualBox Host-Only 网卡，点击「开始监控」。页面显示可映射链路的每秒报文数和速率，再次点击可停止；上传新拓扑也会停止采集。无法识别的设备不会阻止其他链路监控；只识别一端的链路标记为「单端」，数值仅反映该端可观察的流量，未能映射的链路标记为「未覆盖」。

程序按拓扑设备 ID 从本机 VirtualBox 注册配置识别 eNSP AR 克隆虚拟机的网卡 MAC，不支持未识别的设备类型。采集依据当前环境观察到的 UDP 10000–10099 封装，过滤 4 字节载荷的周期报文。数值是封装报文的估算速率，并非设备接口精确统计；其他 eNSP 版本或设备的封装方式可能不同。

拓扑图下方的数据包分析面板显示最近 200 条已匹配连线的报文，可按协议筛选或清空。解析基于观察到的 UDP 载荷中的以太网帧，显示地址、协议、端口或协议类型；鼠标悬停可查看外层 UDP、VLAN 和 TTL。记录只保存在内存中，启动新监控或更换拓扑会清空；未识别或截断的数据以未知信息显示。

选择报文可查看自动分析：包含内层帧、IP 和常见协议首部信息，并提示可识别的截断或长度错误。TCP RST、ICMP 差错等只描述单个报文的含义，不能据此单独判断故障；IPv6 扩展首部和应用负载不作详细解析。



## 跨进程数据共享

拓扑与报告只保存在 Web 服务的内存中，重启后清空。独立的 MCP 进程通过本机 5000 端口读取当前 Web 服务中的报告，因此需要先启动 Web 服务并上传拓扑。上传新拓扑时报告缓存自动清空。独立 stdio 进程与 Web 服务的 Telnet 会话不共享。

## 技术要点

- **默认扫描端口**：2000-2099（eNSP 设备 Telnet 端口默认范围）
- **多设备会话**：可同时管理多个设备，实际数量受本机资源限制
- **多 Tab 终端**：每个设备独立的输出区域和输入框
- **拓扑报告**：仅在 Web 服务运行期间保存，MCP 通过本机 HTTP 接口读取
- **Python 全栈**：Flask 后端 + 原生 HTML/CSS/JS 前端，零前端构建工具

## MCP 客户端配置

使用 `python app.py` 时，MCP SSE 与 Web 服务一同启动。支持 SSE 的客户端可连接 `http://127.0.0.1:5001/sse`。

也可在本机使用 stdio 模式。以下配置仅作示例，请将 `cwd` 修改为包含 `mcp_server.py` 的应用目录，并确保客户端能找到安装了项目依赖的 Python：

```json
{
  "mcpServers": {
    "learn-to-datanetworking": {
      "command": "python",
      "args": ["mcp_server.py"],
      "cwd": "E:\\Documents\\GitHub\\Learn-to-DataNetworking\\LearnToeNSP2.5"
    }
  }
}
```

项目中的 `mcp.json` 可作为格式参考，但其路径可能来自其他环境，使用前请检查并修改。也可单独启动 MCP：

```powershell
python mcp_server.py       # stdio
python mcp_server.py sse   # SSE，监听 5001 端口
```

独立 stdio 进程与 Web 服务的设备会话不共享；需要时请在同一 MCP 进程中连接设备。拓扑报告和拓扑设备检测通过本机 Web 服务读取，使用前需启动 `app.py` 并上传拓扑。`app.py` 已启动 MCP SSE 时，不要再启动独立 SSE 服务占用同一端口。
